# Test & performance report — WinOrbit 1.0 → 1.2, plus the unreleased 1.3 work

**Test machine:** Windows 11 Home build 26300 · Intel Core i5-12400F (6C/12T) · NVIDIA GeForce GTX 1660 SUPER (driver 32.0.16.1047) · 16 GB RAM · NVMe SSD · one 1920×1080 display at 100 % scaling, 60 Hz · Wallpaper Engine running a black-and-white live wallpaper · Rainmeter tested with a throw-away **portable** Rainmeter 4.5.28 (official signed release) in a temporary folder, removed afterwards.

Dates: 17 November 2026 (1.0), 18 November (1.2 and the idle re-measure), 18–19 November overnight (the 1.3 work, rows marked "19 Nov" or "18 Nov" in §3). Since the night of 18 November the monitor was switched off for part of the testing; window captures used `PrintWindow`, which draws a window's content even then.

## 1. Performance (measured)

| Metric | Target | Result | How |
|---|---|---|---|
| Start-up (process start → island and widgets on screen) | fast | **0.75–0.93 s** release, 0.9–1.05 s debug | Logged by the app from process start time; includes .NET start, wallpaper decode/capture, palette and blur |
| Idle CPU, 5 min, release build | < 1 % | **0.050 %** of the machine (0.60 % of one core) | `tools/bench.ps1`: process CPU time over 300 s. State: main window closed, island + clock + now-playing + **system-monitor widget sampling live** (1.5 s), live-wallpaper snapshots on |
| Idle CPU, 5 min, debug build | < 1 % | 0.061 % of machine | same |
| Idle RAM, release build | < 200–250 MB | **69 MB working set average** (max 86 MB); 165–187 MB private bytes | same run, sampled every 10 s |
| Memory with the main window open | — | ~119 MB working set / ~171 MB private | About & Diagnostics, live |
| Handle / thread leak over 5 min | none | handles 854 → 845; threads constant | same run |
| Network sockets at idle | 0 | **0 TCP, 0 UDP** | `Get-NetTCPConnection` / `Get-NetUDPEndpoint` on the process |
| Installer / installed size | — | 5.9 MB setup → 26.8 MB installed (ReadyToRun) | |
| Portable package | — | 73.7 MB zip (includes the .NET runtime) | |

Notes:
* *Private bytes* includes reserved-but-idle .NET heap; *working set* is the physical RAM actually in use. Both are inside the target.
* WinOrbit's numbers exclude Rainmeter and Wallpaper Engine, which are separate processes (About & Diagnostics shows Rainmeter's usage separately when it runs).
* Animation smoothness: expand/collapse and page transitions are 280–430 ms `DoubleAnimation`s on WPF's composition thread; they were observed smooth at 60 Hz in hardware mode. No frame-time instrumentation was run, so no FPS figure is claimed. While the GPU fallback (below) is active, the settings window animates in software; the island and widgets are unaffected.

Raw data: `docs/bench-idle-release.json`, `docs/bench-idle-debug.json`.

**Re-measured 18 November 2026** (after volume by app, screenshot/download/rain/keyboard-language cards and the island on any edge), release build (ReadyToRun, as installed), started with `--startup`, 30 s settle, then `tools/bench.ps1` for 300 s: **0.078 % CPU of the machine** (0.93 % of one core), **77.5 MB average working set (max 97 MB)**, 169–199 MB private bytes, handles 1126 → 1065, threads 32 → 21 (start-up workers finishing). Same machine; island collapsed, main window closed, no music playing. Raw data: `docs/bench-idle-2026-11-18.json`. The README quotes this run. Opening the main window and every island tab builds their UI and raises the working set to roughly 120 MB until Windows trims it.

Re-check after adding live activities (volume meter, privacy dot, reactive bars, lyrics, clipboard/shelf), release build, 60 s sampled 20 s after start: **0.113 % CPU, 56 MB average working set (max 65 MB), 18 threads, 0 TCP / 0 UDP**. Short sample, so it includes the tail of start-up, and the reactive bars run while music plays; the 5-minute figure above remains the reference.

## 4. Not verified here (and why)

| Item | Status |
|---|---|
| Rainmeter: standard (non-portable) install | Tested with a portable copy only, so detection through the registry and `%APPDATA%\Rainmeter\Rainmeter.ini` is unit-tested but not live. |
| Multiple monitors, scaling ≠ 100 % | Only one 1080p display at 100 %. Code paths are per-monitor-DPI aware (PerMonitorV2 manifest, per-monitor wallpaper layout, per-display island instances) but untested on hardware. |
| Windows tweaks applied for real | Not applied, to avoid changing the test PC's Windows settings. Read paths were exercised (the page shows the current values); write + backup + revert logic is straightforward registry/API code but was not run on this PC. |
| Weather | Network is off by default and wasn't enabled. Parsing is unit-tested. |
| Windows 10 | Not available. The app targets 10 2004+; Mica/Acrylic fall back to WinOrbit's own glass there. |
| Microphone pill in a real call; swipe-to-skip with music playing | Only the previews and the wheel path were checked (sideways scroll reaches the skip code; nothing was playing). |
| Pipe cards from another computer | Only one PC. The pipe admits only the current user and WinOrbit hangs up on remote clients, but that branch was not exercised. |
| Live glass: turning it off without restarting, fullscreen pause, several monitors, Windows 10 | The off switch removes the capture marks and stops capture (code path; checked only by restarting). Fullscreen and screen-off pauses are unit-tested decisions, not watched live. One monitor only. Windows 10 isn't available; the setting is disabled there. |
| Curved glass under software rendering | The shader is switched off whenever a window renders in software (checked in code, and by the `Switched` event); not forced on this PC. |
| Long-running stability | 5-minute benchmarks plus ~45 minutes of continuous development sessions without crash or handle growth; no multi-day soak test. |
